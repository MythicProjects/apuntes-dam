## Tema 1. Alfabeto y símbolos

### Teoría

**Norma 1. Cada letra inglesa tiene un nombre que no coincide con el español.** Al deletrear se dice el nombre de la letra, no su sonido dentro de una palabra. Los fallos aparecen en las letras cuyo nombre se parece al de otra letra española.

**Norma 2. Mayúsculas, minúsculas y letras repetidas tienen fórmulas fijas.**
- Mayúscula = **capital** (o *upper case*): "capital A".
- Minúscula = **small letter** (o *lower case*). Solo se dice si hay riesgo de confusión.
- Dos letras iguales seguidas = **double** + letra: "double S".

**Norma 3. Cada símbolo tiene un nombre fijo.** Algunos cambian según el contexto: el punto es *dot* en direcciones y *point* en números.

**Norma 4. Los signos que van en pareja se dicen con open / close** (o *left / right*).

### Ejemplos

**Alfabeto (pronunciación aproximada)**

| Letra | Suena | Letra | Suena | Letra | Suena |
|---|---|---|---|---|---|
| A | ei | J | yei | S | es |
| B | bi | K | kei | T | ti |
| C | si | L | el | U | iu |
| D | di | M | em | V | vi |
| E | i | N | en | W | dabliu |
| F | ef | O | ou | X | ex |
| G | yi | P | pi | Y | uai |
| H | eich | Q | kiu | Z | zi (AmE) / zed (BrE) |
| I | ai | R | ar | | |

**Letras que más se confunden (norma 1)**
- **A / E / I:** A = "ei", E = "i", I = "ai".
- **G / J:** G = "yi", J = "yei".
- **W / Y:** W = "dabliu", Y = "uai".
- **Z:** "zi" en inglés americano, "zed" en británico.

**Mayúsculas y dobles (norma 2)**
- AA → capital A, capital A.
- ss → double S.
- FF → double capital F.
- Domain name → gmail.com, outlook.es.

**Símbolos (norma 3)**

| Símbolo | Nombre | Símbolo | Nombre |
|---|---|---|---|
| `+` | plus | `,` | comma |
| `-` | minus / hyphen / dash | `:` | colon |
| `.` | dot (direcciones) / point (números) | `;` | semi-colon |
| `%` | percent | `@` | at (at sign) |
| `=` | equals | `" "` | quotation marks (quotes) |
| `x` | times / multiply | `_` | underscore |
| `÷` | divided by | `&` | ampersand (and sign) |
| `?` | question mark | `*` | asterisk |
| `#` | hash / hashtag | `{ }` | braces |
| `/` | (forward) slash / or | `\|` | pipe |
| `\` | backslash | `!` | exclamation mark |
| `[ ]` | (square) brackets | `<` | less than |
| `( )` | parentheses | `>` | greater than |

**Parejas (norma 4)**
- `( [ {` → open parenthesis / open bracket / open brace (left…).
- `) ] }` → close parenthesis / close bracket / close brace (right…).
- `"…"` → open quotes … close quotes.
- `[...]` → write it in square brackets.
- `(...)` → write it in parentheses.

✘ Confundir **slash** (`/`) con **backslash** (`\`). Las URLs usan *slash*; las rutas de Windows, *backslash*.

## Tema 2. Spelling: emails, URLs, rutas y código

### Teoría

Para deletrear, recorre el texto de izquierda a derecha y nombra cada pieza según estas normas:

1. **Palabra real → se dice entera:** *school, orders, login, node*.
2. **Sigla o grupo de letras sin sentido → letra a letra:** *api* → A-P-I, *srv* → S-R-V, *npm* → N-P-M.
3. **Números de un identificador → dígito a dígito:** *02* → zero two, *92* → nine two.
4. **Números que son una cantidad → como número:** *id=42* → forty-two, *>= 10* → ten.
5. **Códigos hexadecimales (colores) → siempre dígito a dígito:** *5733* → five, seven, double three.
6. **Mayúsculas → solo si importan:** "Images with a capital I", "capital C".
7. **Espacios → solo en comandos y código,** donde cambian el resultado: "space".
8. **Símbolos → por su nombre** (Tema 1). Los combinados se leen pieza a pieza.

### Ejemplos

**Emails (normas 1, 2, 3)**
- `admin@school.com` → admin, at, school, dot com.
- `j.garcia@outlook.es` → J, dot, garcia, at, outlook, dot E-S.
- `dev_maria-92@outlook.es` → D-E-V, underscore, maria, hyphen, nine two, at, outlook, dot E-S.

**URLs y hostnames (normas 2, 3, 4)**
- `https://api.shopnow.com/v2/orders?id=42` → H-T-T-P-S, colon, slash, slash, A-P-I, dot, shopnow, dot com, slash, V two, slash, orders, question mark, I-D, equals, forty-two.
- `srv-db-02.internal.local` → S-R-V, hyphen, D-B, hyphen, zero two, dot internal, dot local.

**Rutas (norma 6)**
- `/Images/` → slash, images with a capital I, slash.
- `C:\Users\Admin\Documents\app.config` → capital C, colon, backslash, Users with a capital U, backslash, Admin with a capital A, backslash, Documents with a capital D, backslash, app, dot, config.

**Colores (norma 5)**
- `#FF5733` → hash, double capital F, five, seven, double three.
- ✘ "five thousand seven hundred thirty-three".

**Comandos y código (normas 7 y 8)**
- `git commit -m "fix: login bug"` → git, space, commit, space, dash M, space, open quotes, fix, colon, space, login, space, bug, close quotes.
- `npm install @types/node --save-dev` → N-P-M, space, install, space, at, types, slash, node, space, double dash, save, dash, dev.
- `if (x !== null && y >= 10) { return true; }` → if, space, open parenthesis, X, space, exclamation mark, double equals, space, null, space, double ampersand, space, Y, space, greater than or equal to, space, ten, close parenthesis, space, open brace, space, return, space, true, semicolon, space, close brace.

**Símbolos combinados (norma 8)**

| Escrito | Se dice |
|---|---|
| `!==` | exclamation mark, double equals |
| `&&` | double ampersand |
| `>=` | greater than or equal to |
| `--` | double dash |
| `//` | double slash |

## Tema 3. Familias de palabras IT

### Teoría

**Norma 1. De un verbo salen otras formas añadiendo un sufijo.** Cada sufijo indica la categoría de la palabra:

| Categoría | Qué expresa | Sufijos |
|---|---|---|
| Nombre (N) | La acción o su resultado | -ment, -tion / -ation, -age, -ance, -al |
| Persona / herramienta | Quien o lo que hace la acción | -er, -or |
| Adjetivo "ya hecho" | Algo que ha recibido la acción | -ed |
| Adjetivo "se puede" | Algo que puede recibir la acción | -able |
| Forma -ing | El proceso; se usa en collocations | -ing |

**Norma 2. Algunos verbos no cambian al convertirse en nombre:** *test, upload, download, upgrade, design, use, program*.

**Norma 3. El hueco te dice qué categoría necesitas:**
- Detrás de **the / a / more / your / his** → **nombre**.
- Detrás de **is / are / very / much more** → **adjetivo**.
- Si el sujeto **hace** algo (muestra un error, ejecuta) → **persona o herramienta**.
- Si la frase dice que algo **se puede** hacer → **-able**. Si dice que **ya se ha hecho** → **-ed**.

### Ejemplos

**Tabla completa (normas 1 y 2)**

| Verb | Noun | Person / tool | Adjective | Collocation |
|---|---|---|---|---|
| develop | development | developer | developed | develop a mobile app |
| test | test | tester | tested | run a test |
| deploy | deployment | deployer | deployed | deploy to production |
| program | program | programmer | programmed | write a program |
| store | storage | storage device | stored | store data |
| install | installation | installer | installed | install an update |
| upload | upload | uploader | uploaded | upload a file |
| download | download | downloader | downloadable / downloaded | download an app |
| maintain | maintenance | maintainer | maintained / maintainable | maintain the code |
| retrieve | retrieval | retriever | retrievable | retrieve data |
| compile | compilation | compiler | compiled | compile the code |
| upgrade | upgrade | upgrader | upgraded | upgrade the system |
| emulate | emulation | emulator | emulated | run an emulator |
| simulate | simulation | simulator | simulated | run a simulation |
| permit | permission | administrator | permitted | grant / deny permission |
| use | use | user | used / usable | user interface |
| configure | configuration | configurator | configured | configure a server |
| design | design | designer | designed | design the UI |
| connect | connection | connector | connected | connect to the database |
| encrypt | encryption | encrypter / encryptor | encrypted | encrypt passwords |
| authenticate | authentication | authenticator | authenticated | two-factor authentication |
| optimize | optimization | optimizer | optimized | optimize performance |
| validate | validation | validator | validated | validate user input |

**Trampas de la tabla**
- ✘ *storement* → ✔ **storage**.
- ✘ *emulator* como nombre → ✔ **emulation** (*emulator* es la herramienta).
- ✘ *optimization* como persona → ✔ **optimizer**; adjetivo ✔ **optimized**.
- ✘ *maintainance* → ✔ **maintenance**.

**Huecos resueltos (norma 3)**

*Detrás de the / more / your → nombre*
- We need more **storage** space on the server for all the user photos. (STORE)
- The **development** of the new login feature took three weeks. (DEVELOP)
- The **deployment** to the production server failed last night, so the website was down. (DEPLOY)
- The app needs your **permission** before it can use the camera. (PERMIT)
- Two-factor **authentication** makes the login process much more secure. (AUTHENTICATE)

*El sujeto hace algo → herramienta*
- The **compiler** showed an error on line 42, so the code didn't build. (COMPILE)
- We tested the app on an Android **emulator** because we didn't have a real phone. (EMULATE)

*Se puede hacer → -able*
- The app is free and **downloadable** from Google Play. (DOWNLOAD)
- Clean, well-documented code is much more **maintainable**. (MAINTAIN)

*Ya se ha hecho → -ed*
- All passwords are **encrypted** before they are saved in the database. (ENCRYPT)

## Tema 4. Collocations IT

### Teoría

**Norma 1. Una collocation es una combinación de palabras que los nativos usan siempre juntas.** No se deduce por lógica ni se traduce del español: se memoriza. Por ejemplo, un test se *run* (ejecuta), no se *make*.

**Norma 2. Para encontrar la palabra que NO va,** une cada opción con la palabra en negrita y pregúntate si es una acción real en un proyecto de software. La intrusa suele pertenecer a otro campo: hardware, Git, código o datos.

### Ejemplos

**Ejercicio resuelto (norma 2)**

| Palabra base | Opciones (intrusa en negrita) | Por qué sobra |
|---|---|---|
| run a… | test / script / query / **bug** | Un bug se encuentra o se arregla |
| fix a(n)… | bug / **update** / problem / error | Un update se instala o se lanza |
| …the app | **commit** / launch / deploy / install | Se hace commit de cambios, no de la app |
| push… | changes / code / a commit / **a sensor** | Push es de Git; un sensor es hardware |
| …permission | request / grant / **build** / deny | Build se hace con código |
| …data | store / **debug** / retrieve / fetch | Se depura código, no datos |
| call a(n)… | **repository** / API / function / method | Un repositorio se clona |
| user… | interface / experience / account / **compiler** | El compiler no es del usuario |
| …a bug | find / report / track / **launch** | Se lanza una app o una versión |
| …an update | release / install / roll back / **emulate** | Se emula un dispositivo |

**Collocations para memorizar, por tema (norma 1)**
- **Código:** write / compile / push / commit code.
- **Bugs:** find / fix / report / track a bug.
- **Llamadas:** call a function / a method / an API.
- **Ejecutar:** run a test / a script / a query / a simulation / an emulator.
- **Apps:** launch / deploy / install / download / update an app · deploy to production.
- **Datos:** store / retrieve / fetch / validate data · connect to the database · encrypt passwords.
- **Versiones:** release / install / roll back an update · upgrade the system.
- **Permisos:** request / grant / deny permission.
- **Usuario:** user interface / user experience / user account · two-factor authentication.

## Tema 5. Errores típicos de hispanohablantes

### Teoría

Casi todos los errores vienen de traducir palabra por palabra del español. Son de dos tipos:

- **False friends:** palabras que se parecen al español pero significan otra cosa.
- **Estructuras copiadas:** el orden o la preposición del español aplicados al inglés.

**Norma 1. False friends.** Aprende el significado real de cada palabra:

| Palabra inglesa | Significa | No significa |
|---|---|---|
| actually | en realidad | actualmente (= *currently*) |
| realise | darse cuenta | realizar (= *do / run / carry out*) |
| introduce | presentar a alguien | introducir datos (= *enter*) |
| dominate | dominar por la fuerza | dominar un tema (= *be proficient in*) |

**Norma 2. Orden del adjetivo: a + (very) + ADJ + N.** El adjetivo va delante del nombre. Delante de vocal, *a* pasa a ser *an*.

**Norma 3. No añadas "person" a un nombre que ya es una persona:** *a listener, a team player, a problem-solver*.

**Norma 4. Good / bad at + -ing / N.** La preposición es *at*, nunca *in*, y detrás va -ing o un nombre.

**Norma 5. Good es adjetivo; well es adverbio.** Para decir *cómo* haces algo (con un verbo), usa *well*.

**Norma 6. Enjoy / like + -ing.** *Enjoy* nunca lleva *to* + verbo.

**Norma 7. Acción que empezó en el pasado y sigue → have / has been + -ing + for / since.**
- **for** + duración: for three years, for six months.
- **since** + momento de inicio: since 2023, since September.

**Norma 8. Los nombres abstractos en general van sin *the*:** *communication, teamwork, security*.

**Norma 9. Incontables: sin plural y sin *a*:** *experience, knowledge, information, advice, software, data*.

**Norma 10. Tell + persona; say sin persona detrás.** *Tell me*, ✘ *say me*.

**Norma 11. Para indicar finalidad o tras ciertos nombres/adjetivos: to + V (infinitivo).** *Permission to access, keen to develop*. ✘ *for* + V.

**Norma 12. Preposiciones fijas:** *familiar with, proficient in, experience with/in, keen to*.

**Norma 13. Tiempo continuo = am / is / are + -ing.** El verbo siempre lleva -ing.

**Norma 14. Palabras compuestas IT:** *database* (una palabra), *programmer* (no *programator*), *deploy* es verbo y su nombre es *deployment*.

**Norma 15. La edad se dice con *be*:** I am 23 (years old). ✘ *I have 23 years*.

**Norma 16. Las profesiones llevan siempre *a / an*** y el adjetivo va delante (norma 2): I am **a junior** developer.

**Norma 17. Tercera persona singular (he, she, it, my company, my boss) en presente simple → verbo + -s.** En negativa: **doesn't** + verbo base. ✘ *my company make*, ✘ *my boss don't*.

**Norma 18. Need + to + V.** ✘ *I need practise*. Nota: *practise* es el verbo en británico y *practice* el nombre; en americano, *practice* para los dos.

**Norma 19. Preguntas con verbos normales: (Wh-) + do / does + sujeto + verbo base.** El verbo principal nunca se pone delante del sujeto; eso solo ocurre con *be*, *can*, *have*… ✘ *What means…?* ✘ *How works…?*

**Norma 20. El sujeto es obligatorio.** Si no hay sujeto real, se usa *it*: Is **it** possible…? It's important… ✘ *Is possible…?*

**Norma 21. Collocations de rutina:** **have** meetings (✘ *do meetings*) · **run** tests (✘ *realise tests*).

### Ejemplos

**False friends (norma 1)**
- ✘ We **realised** all the tests on the new version yesterday. → ✔ We **ran** all the tests on the new version yesterday.
- ✘ The app **actually** has 500 users. → ✔ The app **currently** has 500 users.
- ✘ **Actually** I'm learning React. → ✔ **Currently** I'm learning React. / I'm currently learning React.
- ✘ Please **ingress / introduce** your password again. → ✔ Please **enter** your password again.
- ✘ I **dominate** SQL and Python. → ✔ I'm **proficient in** SQL and Python.

**Orden del adjetivo (norma 2)**
- ✘ I'm a person very organised. → ✔ I'm a **very organised person**.
- ✔ I'm **an** organised person.

**Sin "person" (norma 3)**
- ✘ I'm familiar with Git and I'm a good listener person. → ✔ I'm familiar with Git and I'm **a good listener**.

**Good at + -ing (norma 4)**
- ✘ I'm good in solving problems. → ✔ I'm good **at solving** problems.
- ✘ She is good at explain technical things. → ✔ She is good at **explaining** technical things.

**Good / well (norma 5)**
- ✘ I work good under pressure. → ✔ I work **well** under pressure.

**Enjoy + -ing (norma 6)**
- ✘ I enjoy to work in a team. → ✔ I enjoy **working** in a team.

**Have been + -ing + for (norma 7)**
- ✘ I work with Linux since three years. → ✔ I **have been working** with Linux **for** three years.
- ✘ I work with Docker since one year. → ✔ I have been working with Docker **for a year**.
- ✔ I have been working with Docker **since** 2025.

**Sin *the* (norma 8)**
- ✘ One of my strengths is the communication. → ✔ One of my strengths is **communication**.

**Incontables (norma 9)**
- ✘ I have a lot of experiences with databases. → ✔ I have a lot of **experience** with databases.

**Tell / say (norma 10)**
- ✘ People often say me that I'm very patient. → ✔ People often **tell me** that I'm very patient.

**To + V (norma 11)**
- ✘ You must give permission to the app for access the camera. → ✔ You must give the app permission **to access** the camera.
- ✘ I have interest to develop… → ✔ I am **keen to develop**…

**Preposiciones fijas (norma 12)**
- ✘ I am familiarized with Git. / I am familiar to Git. → ✔ I am **familiar with** Git.

**Continuo (norma 13)**
- ✘ I am learn Java. → ✔ I am **learning** Java.

**Palabras IT (norma 14)**
- ✘ We save all the information in a base of data. → ✔ We save all the information in a **database**.
- ✘ The programator found the bug in five minutes. → ✔ The **programmer** found the bug in five minutes.
- ✘ I have to make a deploy of the app tonight. → ✔ I have to **deploy** the app tonight.

## Tema 6. Hard skills

### Teoría

**Definición.**
- **Hard skills** = *technical abilities you can learn and measure*. Son habilidades técnicas que se aprenden y se pueden demostrar: Python, SQL, configurar una red.
- **Soft skills** (Tema 7) = *how you work and deal with people*. Describen cómo trabajas y te relacionas: teamwork, communication, problem-solving.

**Truco para clasificar:** si se aprende en un curso y se puede demostrar con un examen o un certificado, es **hard**. Si describe tu forma de ser o de trabajar con otros, es **soft**.

**Norma 1. Elige la estructura según tu nivel.** Hay tres niveles, de menos a más dominio:

| Nivel | Qué expresa | Estructuras |
|---|---|---|
| **A · Básico** | Sabes hacer algo concreto, lo estás aprendiendo o te interesa | I can + V · I know + N / I know how to + V · I use + herramienta · I am learning + N / how to + V · I am interested in + N / -ing |
| **B · Intermedio** | Tienes experiencia y soltura | I am good / brilliant / excellent at + -ing / N · I have experience in/with + N · I am familiar with + N · I have worked with + N · I am currently learning + N |
| **C · Avanzado** | Dominas el tema o tienes experiencia larga | I have basic knowledge of + N · I have hands-on experience in + -ing · I am proficient in + N · I have a solid grasp of + N · I have been working with X for + tiempo · I am keen to develop my skills in + N |

**Norma 2. Respeta la preposición y lo que va detrás.** *at* + -ing, *with* + N, *in* + N/-ing, *of* + N, *to* + V.

**Norma 3. Escala con sistemas operativos (de menos a más):**
I can install an OS → I have basic knowledge of OS → I am familiar with different OS → I am comfortable working with different OS → I am proficient in OS management.

**Vocabulario clave**
- *hands-on* = práctico, con experiencia real.
- *solid grasp* = buen dominio.
- *proficient* = competente, con soltura.
- *keen to* = con ganas de, predispuesto a.

**Hard skills típicas**
- **DAM / DAW:** HTML, CSS, JavaScript, Kotlin · build responsive websites/apps · object-oriented programming · user interfaces · test interfaces · front-end frameworks · REST APIs · databases · deploying websites/apps.
- **ASIX:** set up servers · configure networks · manage users & permissions · virtualization · backups · troubleshooting · hardware · scripting in Bash.
- **SMI:** las mismas que ASIX, a nivel A y B.
- **Comunes a todos:** read documentation in English · Git + GitHub · SQL · different OS · working with tickets.

### Ejemplos

**Clasificar hard vs soft (Guessing)**

| Hard skills | Soft skills |
|---|---|
| SQL | teamwork |
| Git | time management |
| Linux | adaptability |
| configuring a firewall | patience |
| debugging | communication |
| writing documentation | problem-solving |
| JavaScript | attention to detail |
| network wiring | creativity |

**Nivel A**
- I **can** install an OS.
- I **can** install and configure a Linux server.
- I **know** HTML and CSS.
- I **know how to** set up a virtual machine.
- I **use** Git every day.
- I **use** Linux every day.
- I **am learning** Java.
- I **am learning how to** use Linux.
- I **am interested in** computer assembly.

**Nivel B**
- I am **good at** fixing network problems.
- I'm quite **good at** finding bugs in other people's code.
- I **have experience with** MySQL databases.
- I am **familiar with** Git and GitHub.
- Are you **familiar with** Android Studio?
- I **have worked with** virtual machines.
- I am **currently learning** React.
- I am **currently** learning how to deploy apps in the cloud.

**Nivel C**
- I **have basic knowledge of** coding.
- I **have basic knowledge of** PHP.
- I **have hands-on experience in** deploying web apps.
- She **has hands-on experience in** building REST APIs.
- I am **proficient in** Python and SQL.
- Joan is **proficient in** Kotlin and Java.
- I **have a solid grasp of** networking fundamentals.
- Aina **has a solid grasp of** networking fundamentals.
- I **have been working with** Docker **for** a year.
- We**'ve been working with** Docker **for** six months.
- I am **keen to develop my skills in** cloud security.

**Errores de este tema**
- ✘ I dominate systems. → ✔ I am proficient in systems.
- ✘ Actually I am learning React. → ✔ I am currently learning React.
- ✘ I am familiarized with / familiar to Git. → ✔ I am familiar with Git.
- ✘ I work with Docker since one year. → ✔ I have been working with Docker for a year.
- ✘ I have interest to develop… → ✔ I am keen to develop…

## Tema 7. Soft skills

### Teoría

**Definición.** Las soft skills son cualidades personales: cómo te relacionas, cómo te organizas y cómo reaccionas ante los problemas.

**Norma 1. Estructuras para hablar de tus soft skills:**

| Estructura | Qué va detrás |
|---|---|
| I am + ADJ | un adjetivo |
| I like / enjoy + -ing | un verbo en -ing |
| I'm a + ADJ + person | adjetivo + *person* |
| I work well + contexto | *under pressure, in a team…* |

## Tema 8. Tech jobs

### Teoría

**Norma 1. Plantilla para definir un puesto:** A / An + puesto + is + *someone / a person / a professional* + **who** + verbo en -s… + **for** + destinatario.
- **who** introduce lo que hace. El verbo lleva -s porque el sujeto es singular.
- **for** introduce para quién trabaja.

**Norma 2. La misma definición tiene dos versiones:**
- **Técnica:** para profesionales, con vocabulario preciso (*infrastructure, specs, unit testing*).
- **Sencilla:** para cualquiera, con lenguaje cotidiano y situaciones reales (*the person you call when your computer crashes*).

**Norma 3. Conectores para alargar una definición:**

| Conector | Qué añade | Ejemplo |
|---|---|---|
| such as + N | ejemplos | documentation **such as** API guides |
| as well as + -ing | otra tarea | **as well as** debugging |
| while + -ing | una tarea a la vez que otra | **while** providing technical support |
| responsible for + -ing | responsabilidad | **responsible for** installing hardware |
| focused on + -ing | especialidad | **focused on** converting designs into code |
| for + persona + to + V | finalidad para alguien | **for** anyone **to** learn how to use a tool |
| so (that) + frase | resultado | **so** they work on tasks correctly |
| telling them + what… | explicación | **telling them** precisely what steps to follow |

**Norma 4. El modificador va delante del nombre.**
- Adjetivo + nombre: *clear and structured documentation* (✘ *documentation clear and structured*), *specific instructions* (✘ *instructions specific*).
- Nombre + nombre: *an infrastructure professional* (✘ *a professional of infrastructure*), *a security guard*, *unit testing*.

**Norma 5. translate / convert / transform X into Y** (✘ *in*): translate complex jargon **into** plain language.

**Norma 6. Usa el vocabulario técnico real, no calcos del español:**

| ✘ Calco | ✔ Correcto | Español |

**Definiciones en 2 versiones (normas 1–6)**

*Technical Writer*
- ✘ Borrador: …who writes documentation clear and structured… / …translates complicated IT language in simple language…
- ✔ Técnica: A Technical Writer is someone **who creates clear and structured documentation, such as** API guides, architecture manuals, code references and release notes, **for** developers, engineers or end users.
- ✔ Sencilla: A Technical Writer is someone **who translates complex tech jargon into plain language for** anyone **to** learn how to use a tool or software easily.

*IT Technician*
- ✘ Borrador: …professional of infrastructure… operative systems… basic informatic components… support technic…
- ✔ Técnica (1): An IT Technician is **an infrastructure professional who** installs, configures and maintains hardware, operating systems and core computer components **for** users **to** receive direct first and second level IT support.
- ✔ Técnica (2, mejor): An IT Technician is an infrastructure professional **responsible for installing, configuring and maintaining** hardware, operating systems and core computer components, **while providing** Tier 1 and Tier 2 technical support.
- ✔ Sencilla: An IT Technician is **the go-to tech support person you call when** your computer **crashes**, the printer **stops working**, or you need help installing a new program at work.

*Computer Programmer*
- ✘ Borrador: …professional focus in converting… specific technics… unit proves… instructions specific…
- ✔ Técnica: A Computer Programmer is a professional **focused on converting** software designs and specs **into** functional and optimized code, **as well as debugging and performing** unit testing.
- ✔ Sencilla (1): A Computer Programmer is a person **who** writes specific instructions **for** machines, **so** they work on tasks correctly.
- ✔ Sencilla (2, mejor): A Computer Programmer is a person **who** writes exact line-by-line instructions **for** computers, **telling them** precisely what steps to follow to run a task.

*Cybersecurity Analyst*
- ✔ Técnica: A Cybersecurity Analyst is a specialist **who assesses, detects and mitigates** vulnerabilities in networks, applications and computer systems. They apply security controls and monitor security events in a SOC (Security Operations Centre) to prevent data breaches.
- ✔ Sencilla: A Cybersecurity Analyst is a company's digital security guard **who** protects its information from viruses and **stops** cybercriminals **from stealing** or changing confidential data.
- Glosario: mitigar = *mitigate* · vulnerabilidades = *vulnerabilities* (en la diapositiva pone *threats*, pero *threats* son las amenazas) · brecha de datos = *data breach*.

**Norma 2. Cada bloque tiene estructuras fijas:**

| Bloque | Estructura | Qué va detrás |
|---|---|---|

| WHO | [A] works **as** a(n) + puesto | el nombre del puesto |

## Tema 10. Herramientas online, redes sociales y videollamadas

### Teoría

**Norma 1. Para definir un concepto, usa una plantilla fija:**
- Persona → **A person who + V…** (*A person who takes part in a call.*)
- Cosa → **A [thing] that + V…** (*A notification that reminds you…*)
- Acción → **To + V…** (*To send a file to a website.*)
- Grupo de personas → **The people who + V…**

✘ No empieces con *Is…* sin sujeto. ✘ No uses *that* + verbo sin -s para un sujeto singular (*a person that are*).

**Norma 2. Para justificar un True / False,** escribe la palabra (True / False) y después una frase completa que diga lo correcto. Si es falso, corrige el dato.

**Norma 3. Para dar consejo sobre buenas maneras, usa should + V** (debería): *He should mute his microphone.*

**Norma 4. Verbos de cámara y micrófono:** **turn on / turn off**, **mute / unmute**, **share** your screen. ✘ *put off*.

**Herramientas**
- **Trello:** las tareas son **cards**, organizadas en **lists** dentro de un **board**.
- **Slack:** enviar mensajes, compartir archivos y colaborar.
- **Zoom / Microsoft Teams / Google Meet:** videollamadas y screen-sharing gratis.
- **Instagram:** puedes etiquetar (tag) a gente en tus fotos y en las de otros.

### Ejemplos

**Definiciones (norma 1)**

| Concepto | Definición |
|---|---|
| Influencer | A normal person who is very influential because they have a lot of followers on social media. |
| Followers | The people who follow your account on social media. |
| Host | The person who creates and runs a video call or online meeting. |
| Participant | A person who takes part in a call (or a competition). |
| Screen-sharing | Showing your phone or PC screen to the other people in a call. |
| Upload | To send your content (photos, videos, files) to a website, app or social network. |
| Tag | To mark or mention a person in a photo or post on social media. |

**True or false justificado (norma 2)**
1. Influencers look like normal people. **True.** They look like normal people, but they are very influential.
2. People trust traditional adverts more than influencers. **False.** People trust influencers more because they seem like ordinary people.
3. At the beginning, companies paid influencers a lot of money. **False.** At first, companies gave them free products.
4. Influencers usually choose one topic, for example fashion or travel. **True.** They usually focus on one topic (a niche).
5. On Trello, tasks go on boards. **False.** Tasks go on cards.
6. With Slack, you can send messages and share files. **True.** You can also work together in other ways.
7. Zoom, Microsoft Teams and Google Meet have free video calls. **True.** They also have free screen-sharing.
8. The host of a video call should put the invitation on social media. **False.** The host should only send it to the right people.
9. In a video call, participants should keep their microphone on all the time. **False.** They should turn it off (mute it) when they aren't speaking.
10. On Instagram, you can also tag other people's photos. **True.** You can tag people in your own photos too.

## Tema 11. Listening

### Teoría

**Norma 1. No necesitas entenderlo todo: localiza el dato que piden.** Lee las preguntas antes del audio y marca la palabra interrogativa para saber qué buscas:

| Pregunta | Buscas |
|---|---|
| What / Which | una cosa, un nombre |
| Who | una persona |
| How much / How many | una cantidad |
| Why | una razón (*because…*) |
| Where | un lugar |
| How | una manera |

**Norma 2. Preguntas dobles = dos respuestas.** "How much… and why?" exige la cantidad **y** la razón.

**Norma 3. Huecos con letra inicial (C___ M___):** la letra y la gramática de la frase limitan la palabra. Comprueba si el hueco pide nombre, adjetivo o verbo (Tema 3).

**Norma 4. Responde con frase corta y el sujeto correcto.** Si la pregunta es sobre él, empieza con *He…*, no con *We…* ni *I…*.

**Norma 5. Revisa la ortografía de las palabras largas:** *sophisticated, rudimentary, notifications, experts*.

### Ejemplos

**Podcast: AI chatbots and parental controls (huecos resueltos, norma 3)**

Jim Steyer, the CEO and founder of (1) **Common Sense Media**, says that chatbots are not (2) **human beings**; they're robots.

AI and chatbots have been trained in realms of (3) **data**.

According to Steyer, this is the time when kids are really (4) **guinea pigs**, as we don't know how it affects them, (5) **suicide** being the most extreme example.

The main problem is that robots masquerade as humans to give (6) **advice** to troubled people.

Now, parents can feel safer. They can (7) **link** their accounts with their teens, change settings such as turning off (8) **memory** record and even (9) getting **notifications** when their children show signs of distress.

However, (10) **experts** like Steyer warn that this is not enough for diverse reasons. First, many parents (11) don't **understand** AI, whereas kids are more technologically (12) **savvy**. Secondly, these are (13) **rudimentary** parental controls, allowing (14) **sophisticated** kids to get around easily. Finally, big tech companies are making billions of dollars in (15) **profit** on the back of children and families.

Young people say parental control cannot have a huge (16) **impact** on their presence on the Internet, but it can't (17) **hurt** to have them in place.

## Tema 12. Elevator pitch (presentación personal)

### Teoría

**Definición.** Un elevator pitch es una presentación personal muy corta, de 30 a 60 segundos (lo que dura un trayecto en ascensor). Sirve para que una empresa o un contacto sepa quién eres y qué ofreces. Junta los temas 6, 7 y 9.

**Norma 1. Cuatro bloques, siempre en este orden:**

| Bloque | Pregunta | Contenido |
|---|---|---|
| **HOOK** | Who? | Quién eres: nombre, qué estudias, dónde, en qué curso y qué área te interesa |
| **SKILLS** | What do you do? | Hard skills: tus 2–3 tecnologías fuertes, qué sabes hacer con ellas, qué aprendes ahora y desde cuándo |
| **PROOF** | How do you work? | Soft skills demostradas con un hecho (proyecto, trabajo o hobby) y su resultado |
| **GOAL** | What are you looking for? | Qué buscas (prácticas, primer trabajo, contacto), qué empresa o equipo, qué quieres aprender y qué ofreces |

**Norma 2. Prepara cada bloque con estas preguntas:**
- **HOOK:** Who are you? What are you studying, and where? Which year are you in? What area of IT interests you most?
- **SKILLS:** Which three technologies or tools do you know best? What can you build, fix or configure with them? What are you learning right now? How long have you been using your strongest tool?
- **PROOF:** Which two soft skills describe you best? When did you show one of them? What do classmates or colleagues usually say about you? What was the result?
- **GOAL:** Are you looking for an internship, a first job or a contact? What kind of company or team would you like to join? What do you want to learn there? What can you offer them from day one?

**Norma 3. Demuestra, no enumeres.** Un adjetivo suelto (*I'm reliable*) convence poco. Añádele un hecho y un resultado: *in my last class project, I organised the tasks for a team of four and we delivered on time*.

**Norma 4. Sube el nivel de las estructuras.** Usa las de nivel B y C del Tema 6 (*I'm proficient in…, I have hands-on experience in…*), no solo *I can / I know*.

**Norma 5. Adapta el GOAL a la empresa y cierra con cortesía:**
- I'm looking for + N: *an internship, a first job*.
- … where I can + V: *where I can work on real front-end projects*.
- I'd love to + V: *I'd love to contribute to that*.
- I'd be glad to + V: *I'd be glad to tell you more about my project*.

**Norma 6. "Estudiante de…" = a + curso / estudios + student.** *A second-year DAM student*, *a final-year App Development student*. ✘ *a student of …*

### Ejemplos

**Nivel básico (Toni)**

> Hello, my name is Toni. I am a student of … in Mallorca. I can install operating systems and configure a network. I know Linux and Windows Server. I am patient and organised. I want to work as a system administrator. I am looking for an internship in an IT department. Thank you. Nice to meet you.

Qué falla: solo usa estructuras de nivel A, enumera adjetivos sin demostrarlos (norma 3) y dice *a student of …* (norma 6).

**Nivel intermedio (Laura)**

> Hi, I'm Laura. I'm in my second year of Web Development at CIFP Borja Moll, in Palma. I'm good at building responsive websites, and I have experience with JavaScript and MySQL. Right now I'm learning React. I'm a reliable person: in my last class project, I organised the tasks for a team of four and we delivered on time. I'm looking for an internship where I can work on real front-end projects. I'd love to hear more about your company.

Qué mejora: usa estructuras de nivel B, demuestra *reliable* con un hecho y un resultado, y cierra con cortesía.

**Nivel avanzado ✔ (Marc)**

> Hi, I'm Marc, a final-year App Development student with a strong interest in mobile apps that solve everyday problems. I'm proficient in Kotlin and I have hands-on experience in building Android apps with Firebase. I recently built an app that helps students share notes, which is now used by three classes at my school. On top of that, I'm the person my team comes to when something breaks, because I enjoy finding the root of a problem. I've seen that your company is developing its own booking app, and I'd love to contribute to that during my internship. I'd be glad to tell you more about my project.

Por qué es el mejor: tiene un HOOK con interés concreto, usa estructuras de nivel C, da una prueba con un resultado medible (*used by three classes*), demuestra la soft skill sin nombrarla y adapta el GOAL a la empresa.

**Modelo DAM para el examen**

> **HOOK** Hi, I'm [name], **a second-year DAM student** at [school] in [city], with a strong interest in [area].
> **SKILLS** **I'm proficient in** Java and SQL, and **I have hands-on experience in** designing PostgreSQL databases. **I have been working with** Git and GitHub **for** two years, and right now **I'm learning** React.
> **PROOF** **I'd describe myself as** detail-oriented: in my last class project, I reviewed my team's code before every push and we delivered with no critical bugs. **People often tell me that I** stay calm when things break.
> **GOAL** **I'm looking for** an internship **where I can** work on real back-end projects. **I'd love to** hear more about your company.

**Checklist antes de entregar**
- [ ] Cuatro bloques en orden: hook, skills, proof, goal.
- [ ] Cada soft skill con un hecho y un resultado.
- [ ] Estructuras de nivel B y C, no solo *I can / I know*.
- [ ] *a second-year DAM student*, nunca *a student of…*
- [ ] Edad con *be*: *I am 23*.
- [ ] **good at** + -ing · **familiar with** · **proficient in** · **experience with** (sin plural).
- [ ] **have been + -ing + for** + duración; nunca *since three years*.
- [ ] **currently** (actualmente), no *actually*.
- [ ] **tell me**, no *say me*.
- [ ] Nada de *I dominate*: usa **I am proficient in**.
- [ ] Preguntas con **do / does**: *What does it mean?*
